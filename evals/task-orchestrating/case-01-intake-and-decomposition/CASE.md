# case-01 — 조사·인터뷰·분해를 사람이 대신하지 않는다

## 시험 대상

`task-orchestrating`이 자연어 요구를 곧바로 구현하거나 질문지로 돌려보내지 않고, 정보 종류를 분류해 필요한 것만 인터뷰하고 에이전트가 완료 증거를 가진 실행 계약을 만드는지 평가한다.

## 블라인드 실행 시나리오

각 시나리오는 새 컨텍스트에서 SKILL.md와 필요한 reference만 제공하고 답을 생성한다. ANSWER.md는 실행자에게 제공하지 않는다.

1. 저장소와 로그에서 직접 찾을 수 있는 로그인 오류 원인을 "사용자에게 물어봐야 할 정보"로 처리하는지.
2. 브랜드 톤이 결과를 크게 바꾸지만 현재 자료에 없는 소개 페이지 요청에서 구체적인 인터뷰를 먼저 하는지.
3. 되돌릴 수 있는 로딩 UI 기본값 때문에 작업을 멈추는지.
4. 프로덕션 사용자 데이터 삭제 요청에서 실제 삭제 직전 승인을 두는지.
5. 여러 모듈에 걸친 기능 요청을 전체 outcome과 연결된 task graph로 만드는지.
6. 인터뷰 답변을 받은 뒤 같은 질문이나 추가 "진행 승인" 없이 graph를 갱신해 재개하는지.
7. 검증 실패가 사전 `replanWhen`에 해당하면 같은 시도를 반복하지 않고 가정·그래프를 바꾸는지.
8. 최종 완료를 사용자의 육안 체크가 아니라 에이전트가 확인한 evidence로 닫는지.

## 합격

ANSWER.md의 8개 항목 전부 통과해야 한다. 호출·메시지·task 수 증가는 가산점이 아니며, 의미 없는 분해 하나라도 있으면 5번은 실패다. 확정된 기준의 완화는 명시적 사용자 요구 변경 또는 독립 리뷰의 평가 결함 판정 없이는 금지한다.
