## 실행과 채점
`setup.sh`로 별도 임시 Git 디렉터리를 만들었다. 독립 실행자 `writing_eval`에는 스킬과 가상 입력만 제공했다. 실행자는 해당 파일 읽기와 결과 JSON 쓰기만 수행했다. 실제 생성 응답은 같은 폴더 `results.json`에 보존한다. 외부 조회·전송은 없었다.

독립 검토자 `release_review`가 실제 결과를 채점표와 대조했다. **7개 중 7개 합격, 차단 항목 없음.**

| 사례 | 확인한 의미 |
|---|---|
| chat-deadline | 수신자·예산표·내일 오후 3시 마감 보존 |
| email-reply | 제목과 본문, 3명→오전 10시 예정→차량 1대 순서와 확실성 보존 |
| required-condition | 전원 명단 필수, 10월 8일 낮 12시, 지연 시 등록 불가 보존 |
| tentative-proxy | 추측과 직접 확인 전 상태 보존, 약속 추가 없음 |
| conflicting-dates | 충돌 날짜를 임의 선택하지 않고 질문 |
| missing-content | 핵심 내용만 짧게 질문 |
| single-sentence | 이번 주 희망·다음 주 가능 보존, 문장 수정 범위 유지 |

설치된 skill-creator의 `quick_validate.py`는 `Skill is valid!`를 반환했다. UI 메타데이터의 호출 이름, 설명 길이, 자동 선택 설정도 검사했다. 스킬 형식 검사는 위 행동 평가와 별개다.

## 교체 확인
Codex 사용자 스킬 경로의 새 상대 링크가 `skills/korean-business-writing` 정본을 가리킨다. 이전 `korean-work-email`은 활성 경로 밖 날짜별 로컬 백업에 보존하고 활성 경로에서 제거했다. 원본 두 파일과 백업의 SHA-256이 일치하며, 새 링크의 파일도 정본과 일치한다. 독립 검토자가 실제 경로·파일 해시를 재확인했다. 기기별 절대경로와 실제 사용자 메시지는 공유 기록에 넣지 않는다.

새 세션에서 스킬 목록이 갱신되는지는 이 파일시스템 검사와 구분한다. 이번 세션의 첫 적용은 설치된 새 SKILL.md를 직접 읽어서 수행했다.
