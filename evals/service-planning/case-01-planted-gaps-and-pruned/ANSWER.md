# 정답지 — case-01 (채점자 전용: critic 에게 주지 말 것)

## 심은 것
- **정탐 ① (cat4 UI 상태)**: §5 캡처 화면이 Ideal 만 — empty/loading/error 누락. (리스트 화면은 §4 에 빈 상태가 있으니, 누락은 *캡처 화면*에 특정.)
- **정탐 ② (cat5 대안/예외)**: §6 가 Primary 만 — alternate(임시저장 등)·exception(저장 실패·오프라인·중복) 누락.
- **정직성**: §1 "이미 수많은 독서가에게 검증된 인기 패턴으로 PMF 가 확인되었다" — 사용자/데이터 없는 가짜 검증 주장.

## 오탐 함정 (누락 아님 — 올리면 감점)
- **cat2 역할/페르소나**: §3 에 "(스코프상 제외 — n=1)" 명시. n=1 은 rubric pruning 에서 ❌ → 누락 아님.
- **auth/계정 (스캐폴딩)**: §7 에 "(인증·권한·온보딩 제외)" 명시. n=1 은 스캐폴딩 ⚠(데이터수명주기·설정만) → auth 누락 아님. critic anti-pattern "n=1 에 auth 없다고 BLOCKER 걸지 말 것" 직격.

## 채점표 (메인이 critic 출력으로 채점)
| # | 항목 | 기준 |
|---|---|---|
| 1 | **정탐: UI 상태** | 캡처 화면 5상태 미흡(empty/loading/error 누락)을 BLOCKER/WARNING 으로 잡음 (cat4 귀속) |
| 2 | **정탐: 예외** | alternate/exception 플로우 누락을 잡음 (cat5 귀속) |
| 3 | **정직성** | "검증된 인기/PMF 확인" 가짜 주장을 **정직성 위반**으로 잡음 (시장검증 요구가 아니라 *가짜 주장*으로) |
| 4 | **오탐 억제: 역할** | "(스코프상 제외)" 된 역할(cat2)을 누락/BLOCKER 로 **안** 올림 |
| 5 | **오탐 억제: auth** | n=1 pruned 인증/계정을 누락/BLOCKER 로 **안** 올림 |
| 6 | **형식** | `## Completeness 검증` BLOCKER/WARNING/정직성 위반/커버리지 구조 준수 |

## 합격선
{1,2,3} 중 **≥2** + {4,5} **둘 다 클린** + 6. 정탐 약하거나 정당 제외 오탐(특히 #4·#5) = 불합격.

## 알려진 함정 (이 케이스가 잡으려는 공정 결함)
- critic 이 n=1 인데 인증/권한/온보딩/알림 누락을 BLOCKER 로 쏟아냄 (#5) — pruning 무시(가장 흔한 critic 실패)
- "(스코프상 제외)" 표기를 못 보고 역할/페르소나 누락 처리 (#4)
- 가짜 PMF 주장을 통과시키거나, 반대로 "시장 검증 안 됨"을 누락으로 지적(범위 오해 — 이건 완성 검증이지 시장 검증 아님) (#3)
- 캡처 화면 누락을 리스트 화면 빈 상태로 뭉뚱그려 "5상태 충족" 오판 (#1)
