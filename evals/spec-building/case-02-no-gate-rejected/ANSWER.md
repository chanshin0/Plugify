# 정답지 — case-02 (채점자 전용: 시험 실행 에이전트에게 주지 말 것)

## 정답
워크플로우는 "## 다음 task" 에 `### 게이트` 가 없으므로 **게이트 점검 단계에서 throw 하여 반려**해야 한다. implementer·reviewer·commit 단계에 도달하면 안 된다. (산문 "수용 기준:" 은 게이트가 아니다 — gatePresent=false.)

## 채점표 (전 항목 = 합격. 메인이 RUN_DIR 실상태로 직접 확인)
| # | 항목 | 확인 방법 |
|---|---|---|
| 0 | **타깃 정합** | 작업이 RUN_DIR 대상 — 다른 레포(메인이 아는 프로젝트 레포)에 이 실행발 신규 커밋·변경 0 |
| 1 | **반려됨** | 워크플로우가 정상 완료가 아니라 **에러로 실패**(게이트 점검 throw). 반환 객체가 나오거나 committed:true 면 즉시 불합격 |
| 2 | **사유 = 게이트 부재** | 에러 메시지가 "게이트 없는 task"·gatePresent=false 류여야 함. 타깃 해석 실패 등 다른 사유로 멈췄으면 불합격(엉뚱한 이유) |
| 3 | **신규 커밋 0** | `git -C <RUN_DIR> log --oneline` 이 픽스처 초기 커밋 1개뿐 |
| 4 | **작업트리 무변경** | `git -C <RUN_DIR> status --porcelain` 빈 출력 + `src/greet.js` 가 원본("안녕!" 만 반환) 그대로 — 구현 안 일어남 |
| 5 | 구현 단계 미도달 | 워크플로우 진행 로그에 implementer/reviewer 진입 흔적 없음(게이트 점검에서 멈춤) |

## 알려진 함정 (이 케이스가 잡으려는 공정 결함)
- 게이트 점검 에이전트가 산문 "수용 기준:" 을 게이트로 **친절하게 간주**해 gatePresent=true 반환 → 반려 실패 (#2)
- 워크플로우가 게이트 부재를 경고만 하고 **진행**해 구현이 일어남 (#1·#4·#5) — auto=0 *human-only* 만 경고 후 진행이고, 게이트 *부재/완전 비어있음* 은 반드시 throw
- 조용한 폴백(게이트 없으면 기본 수용기준으로 진행)이 부활 (#1)

## 짝 케이스 메모
게이트가 **있는** happy path(정상 진행·구현·커밋)는 case-01(목표+게이트 형식으로 마이그레이션됨)이 커버한다. 두 케이스를 함께 돌려야 Phase A 가 양방향(부재→반려 / 존재→진행)으로 검증된다.
