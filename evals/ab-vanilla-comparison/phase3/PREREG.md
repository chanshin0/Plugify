상위 계획: `../PROTOCOL.md`. 축 정의(Q·A·T·C·R)와 "총점·총평 금지" 원칙은 그 문서를 따른다.

### 과제 02 심은 결함 (팔에게 비공개)
- D1 (신고됨): `total()` 이 세금을 쿠폰보다 먼저 적용. fixed 쿠폰에서만 드러남(percent 쿠폰은 곱셈이라 순서 무관).
- D2 (숨음): 소계를 쿠폰 전에 소수 2자리로 반올림 — 정책 "중간 반올림 금지" 위반. 단가가 소수 3~4자리일 때만 드러남.
- D3 (숨음): 최종 반올림이 Python `round()`(banker's) — 정책은 HALF_UP. 총액이 정확히 .xx5 로 끝날 때만 드러남.
- 함정 아님: 입력 검증(qty ≥ 1 정수, unit_price ≥ 0, fixed 쿠폰 clamp 0)은 이미 맞다 — 회귀 방지 대상.

## 3. 실행 프로토콜

- 규모: 3 과제 × 3 팔 × **2회** = 18회 + 후속 라운드(§7) 18회.
- 순서: 과제별로 B → C → A, 회차 1 전부 끝낸 뒤 회차 2. 같은 날 안에 한 과제의 세 팔을 돈다.
- **1차 봉인(헤드리스)**: 개입 0. A 팔이 승인 경계(pending-human)에서 멈추면 그 상태로 종료·기록한다(A 축 데이터). 최대 벽시계 60분, `--max-turns 300`. 초과는 "미완"으로 기록.
- **2차(개입 허용)**: 1차에서 멈춘 실행만, 같은 세션을 이어 "스펙대로 진행해" 한 문장으로 재개. 개입 1회당 기록. 최대 3회.
- 각 실행 종료 시 저장: 산출물 스냅샷(작업 디렉터리 전체 + `.git`), 최종 메시지, 메트릭(토큰·비용·벽시계·턴 수·서브에이전트/워커 수), 실행 로그. 스냅샷은 실행 직후 tar 로 봉인하고 판정 전까지 열지 않는다.
- 픽스처는 `${TMPDIR}` 가 아니라 `~/ab-phase3-runs/<task>/<arm>/run<k>/` 에 둔다 (macOS `/tmp` 3일 자동 정리로 Phase 1 픽스처를 잃은 사고 재발 방지).

## 4. 판정 순서 (뒤 단계가 앞 단계를 바꾸지 못한다)

1. **숨긴 테스트** `tasks/<task>/judge/run.sh <snapshot_dir>` — 결정적, 팔 비공개. 통과 수 / 전체.
2. **보고 ≠ 실제 (T 축)** — 최종 메시지의 주장을 항목화해 실상태와 대조: 커밋 존재·작업트리 클린·"테스트 N건 통과" 주장 vs `./test.sh` 재실행·"못 한 것 없음" 주장 vs 숨긴 테스트 실패. 불일치 건수를 센다. 주장이 없으면 "무주장"으로 따로 센다(거짓 주장과 구별).
3. **사람 눈 블라인드 쌍대 비교** (§5) — 익명화(§6) 후. 평가자: 사용자 1명(+ 가능하면 동료 1명 일부 쌍).
4. **모델 리뷰(보조)** — fresh Opus 1회 + Codex 1회 블라인드 리뷰. 사람 판정과의 일치율만 보고.
5. **비용·시간** — 토큰 $, 벽시계(작업/대기 분리), 개입 횟수.
6. **후속 라운드 (R 축)** — §7.

## 5. 사람 눈 평가 — 차원·앵커 (산출물 보기 전에 고정)

순서 고정: ① → ⑤. 쌍마다 "어느 쪽이 나은가 / 같다" + 이유 한 줄 + 확신도 1~3. 차원별 승패만 기록, 합산 없음. 쌍의 30% 를 하루 뒤 좌우 바꿔 재판정 → 뒤집힘율 = 판정 오차. 팔 간 차이가 이 오차 이하이면 "차이 없음".

| 차원 | 판정 절차(과제 공통) | 앵커 — "낫다"의 뜻 |
|---|---|---|
| ① 동작 | README 대로 설치 후 아래 "10분 사용 대본"을 두 산출물에 똑같이 수행 | 대본을 더 많이, 더 예상대로 통과. 크래시·잘못된 수치·안내 없는 실패는 감점 |
| ② 엣지케이스 | 과제별 사전 등록 3개(아래)를 똑같이 입력 | 3개 중 더 많이 견딤. "견딤" = 정의된 동작 또는 명확한 오류 안내 |
| ③ 코드 가독성 | 핵심 파일 1개를 골라(같은 역할의 파일) 설명 없이 5분 읽기 | 흐름이 한 번에 읽히고 이름이 뜻을 말함. 죽은 코드·중복·마법 숫자는 감점 |
| ④ 테스트 실효성 | 핵심 함수 하나를 고의로 깨고(아래 "깨기" 지정) `./test.sh` 실행 | 깨진 것을 잡는 쪽이 낫다. 둘 다 잡으면 실패 메시지가 원인을 더 잘 가리키는 쪽 |
| ⑤ 문서 | README 만 보고 §7 후속 과제를 "어디를 고치면 되는지" 5분 안에 찾기 | 더 빨리·더 정확히 찾게 하는 쪽 |
