# 블라인드 사람 평가 도구

Python 3 표준 라이브러리와 Git이 필요합니다. 자체검사는 Bash와 Node.js도 사용합니다. 리뷰 콘솔은 외부 리소스나 서버 없이 `file://`에서 사용하도록 작성했습니다.

## 1. 익명화

```bash
python3 anonymize.py --task task-01 \
  --in A=/절대경로/팔A스냅샷 \
  --in B=/절대경로/팔B스냅샷 \
  --in C=/절대경로/팔C스냅샷 \
  --out /절대경로/평가자료
```

`--seed 41`을 지정하면 같은 입력 순서에서 같은 배정·쌍 순서를 재현합니다. 실제 블라인드 평가에서는 생략하세요. 기본 시드는 운영체제 난수로 만들며 출력하거나 저장하지 않습니다. `--extra-terms terms.txt`는 줄당 하나씩 추가 식별 용어를 받습니다. 빈 줄은 무시합니다.

출력 구조:

```text
평가자료/task-01/
  X/                      # 새 Git 레포, 커밋 1개
  Y/
  Z/
  manifest.json           # {"X": 파일 수, "Y": 파일 수, ...}
  pairs.json              # 모든 비순서 쌍, 쌍 순서·좌우 무작위화
  SEALED-mapping.json     # {"X": 실제 입력 라벨, ...}, 권한 0600
```

글자는 X, Y, Z, AA, AB… 순서로 확장됩니다. 기존 출력 과제 디렉터리가 있으면 중단하며 덮어쓰지 않습니다. 출력 경로는 입력 스냅샷 밖이어야 합니다. 원본 레포는 읽기만 하며, Git 초기화·스테이징·커밋은 새 복사본에서만 수행합니다.

`.git`, `node_modules`, `.planning`, `.codex`, `.claude`, `AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `*.log`, `.DS_Store`는 위치·대소문자와 관계없이 제외합니다. 심볼릭 링크는 원본 외부 파일 유입을 막기 위해 오류로 처리합니다.

UTF-8로 읽히는 파일 내용과 파일·디렉터리명의 식별 용어를 대소문자 구분 없이 `[TOOL]`로 바꿉니다. 붙여 쓴 제품명도 가리도록 부분 문자열까지 보수적으로 치환합니다. 지정된 트레일러 줄과 이메일 포함 줄은 삭제합니다. 파일명 충돌은 중단합니다. 치환 후 동일 용어 목록으로 경로와 텍스트를 검사하며, 잔존하면 `파일:줄번호`를 출력하고 실패합니다. `[TOOL]` 자체와 겹치는 추가 용어는 거부합니다. 실패한 임시 복사본은 정리합니다.

커밋 메시지는 `snapshot`, 작성자·커미터는 `anon <anon@example.invalid>`, 양쪽 시각은 `2000-01-01T00:00:00Z`입니다. 사용자 Git 설정·훅·템플릿·서명을 상속하지 않습니다. 복사본의 ignore 규칙과 관계없이 모든 포함 파일을 커밋합니다. 파일 수정 시각도 통일합니다.

**판정이 모두 끝날 때까지 봉인 매핑을 열지 마세요.** 평가자에게는 익명 스냅샷·쌍 목록·번들만 전달합니다. 봉인 파일은 별도 보관하세요. 권한 0600은 암호화가 아니며 소유자에게 읽기 권한이 있습니다. 매핑 파일의 실제 라벨은 의도적으로 치환하지 않습니다.

한계: 바이너리는 그대로 복사하므로 이미지·바이너리 내부 정체는 가리지 않습니다. 등록되지 않은 개인명·URL·파일명 관례는 자동 탐지하지 못합니다. 추가 용어를 사전 등록하고 평가자가 보기 전에 운영자가 점검하세요. 파일명·코드 문자열 치환과 메타데이터 제외는 빌드·임포트·외부 호출에 영향을 줄 수 있습니다. 실험에서 이 변형 정책을 동일하게 적용하고, 평가 전 실행 가능성을 확인해야 합니다.

## 2. 번들 생성

```bash
python3 bundle.py /절대경로/평가자료/task-01/X
python3 bundle.py /절대경로/평가자료/task-01/Y
python3 bundle.py /절대경로/평가자료/task-01/Z
```

기본 출력은 스냅샷 옆의 `X.bundle.json`입니다. `--out /다른/경로/X.bundle.json`으로 바꿀 수 있습니다. 출력은 스냅샷 밖이어야 합니다. `.git` 전체, UTF-8 디코드 실패 파일, NUL 바이트 포함 파일, **200 × 1024바이트 초과** 파일을 제외합니다. 제외 수를 콘솔에 표시합니다. 스냅샷의 파일 자체는 변경하지 않습니다.

```json
{"letter":"X","files":[{"path":"src/main.py","content":"print('예시')\n"}]}
```

## 3. 리뷰 콘솔

1. `review-console.html`을 브라우저에서 엽니다.
2. `pairs.json`을 불러오고 익명 번들 여러 개를 선택합니다. 번들은 추가로 불러올 수 있습니다. 봉인 매핑은 불러오지 않습니다.
3. **최초 판정 시작**을 누릅니다. 파일 트리에서 파일을 선택하면 내용이 실행되지 않고 텍스트로 표시됩니다.
4. 각 쌍에 대해 왼쪽·오른쪽·동률, 필수 한 줄 이유, 확신도 1–3을 기록합니다. 저장된 판정은 읽기 전용입니다. `←`, `→`, `=`로 선택하고 `Enter`로 저장합니다. 이유 입력 중 방향키는 커서 이동으로 유지합니다.
5. 한 차원의 모든 쌍을 마치면 **다음 차원 시작**을 누릅니다. 차원 건너뛰기는 불가능하며 이전 차원은 잠깁니다. 마지막 차원에서도 **평가 완료**를 눌러 종료합니다.
6. **JSON 내보내기**로 저장합니다. 판정마다 메모리 배열에 추가하고 브라우저 저장소에 미러링합니다. 새로 열었다면 같은 쌍 목록·번들을 다시 불러온 뒤 **저장된 세션 복구**를 누릅니다. 최근 세션 하나만 복구하며 제출 전 초안은 저장하지 않습니다. 저장소가 차단되면 경고하고 메모리 판정은 유지합니다.
7. **재판정 세션 시작**을 누르면 최초 JSON을 자동 다운로드하고 전체 쌍의 `ceil(30%)`, 최소 1쌍을 무작위 추출해 좌우를 바꿉니다. 선정된 쌍끼리의 진행 순서는 원래 쌍 목록 순서입니다. 동일 표본을 5차원 모두 평가합니다. 새 브라우저에서 같은 쌍·번들과 완료된 최초 판정 JSON을 불러와 재판정만 시작할 수도 있습니다.
8. 최초 판정은 메모리와 복구 자료에도 보관합니다. **이전 최초 판정 JSON**으로 별도 파일을 불러올 수 있습니다. 재판정 중 차원별 뒤집힘율을 표시합니다. 재판정 결과도 별도 JSON으로 내보냅니다.

차원 순서는 반드시 다음과 같습니다.

1. 동작: 직접 10분 써봤을 때
2. 사전 등록 엣지케이스 3개
3. 코드 가독성: 설명 없이 읽힘
4. 테스트가 실제 실패를 잡음
5. 문서만 보고 새 사람이 기능 추가 가능

콘솔은 스냅샷 앱을 실행하거나 10분 사용·엣지케이스 수행을 자동 증명하지 않습니다. 사전 등록한 동일 기준을 양쪽에 적용한 뒤 기록하세요. 평가자·과제마다 별도 세션을 사용하고 원래 `pairs.json`을 함께 보관하세요. 내보낸 JSON에는 매핑·코드 본문이 들어가지 않습니다. 파일명과 내용 자체의 익명성은 익명화 단계가 담당합니다.

뒤집힘율 = **좌우 교환 보정 후 선택이 달라진 판정 수 / 같은 쌍·차원으로 비교 가능한 판정 수**입니다. 동률과 비동률 사이 이동도 불일치입니다. 최초 왼쪽 우세 → 재판정 오른쪽 우세는 같은 후보라면 일치입니다. 비교 대상이 없으면 비율을 계산하지 않습니다. 차원별 분모도 표시합니다. 다른 과제가 같은 쌍 ID를 쓰면 JSON만으로 구분할 수 없으므로 반드시 같은 과제의 쌍 목록과 최초 로그를 사용하세요.

## 판정 JSON 스키마

```json
{
  "session_id": "세션별 고유 ID",
  "started_at": "2026-09-09T00:00:00.000Z",
  "mode": "initial",
  "verdicts": [
    {
      "pair_id": "X-Y",
      "dimension": 1,
      "choice": "left",
      "reason": "같은 입력에서 오류 없이 완료됐다",
      "confidence": 3,
      "at": "2026-09-09T00:10:00.000Z"
    }
  ]
}
```

`mode`는 `initial` 또는 `rejudge`, `dimension`은 위 고정 순서의 정수 1–5, `choice`는 `left`·`right`·`tie`, `confidence`는 정수 1–3입니다. `reason`은 공백만이 아닌 한 줄입니다. 시각은 ISO 8601 문자열입니다. 배열은 차원 순서 → 쌍 목록 순서의 제출 기록이며 각 쌍·차원은 세션당 한 번만 기록합니다. `left`·`right`는 그 세션의 표시 방향입니다. 최초 방향은 `pairs.json`, 재판정 방향은 그 반대로 해석합니다. 재판정 표본은 로그의 쌍 ID로 식별합니다.

## 자체검사

```bash
bash selftest.sh
```

임시 디렉터리에 가짜 레포 세 개를 만들고 익명화 누출 검사, 커밋 수·신원·시각, 봉인 권한, 쌍 목록, 번들 경계, 심볼릭 링크·경로 충돌·덮어쓰기 거부, 잔존 용어 검출을 검사합니다. 실제 HTML의 스크립트를 추출해 `new Function`으로 컴파일한 뒤 `console-test.js`의 DOM 대역에서 차원 순서·필수 입력·재판정·보정·복구를 검증합니다. 임시 자료는 종료 시 삭제합니다. 프로젝트 작업트리를 스테이징하거나 커밋하지 않습니다.

자동 검사는 실제 브라우저의 파일 선택·다운로드·레이아웃·키보드 이벤트를 보증하지 않습니다. 첫 실전 실행은 관찰 대상으로 삼아 `file://` 로드부터 최초 판정, JSON 다운로드, 세션 복구, 재판정까지 실제 브라우저에서 확인하세요.
