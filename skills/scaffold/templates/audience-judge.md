# 심사자 — {{평가자 역할}} 관점 블라인드 채점

> 이 틀의 존재 이유: 내부 품질 검증("맞는가·완전한가")과 별개로, **산출물을 실제로 받아볼 외부인이 통과시킬 것인가**를 미리 시뮬레이션한다. 스폰 시 제작 맥락(왜 이렇게 만들었는지·얼마나 공들였는지)을 **주지 않는다** — 맥락을 아는 심사자는 후하게 채점한다(블라인드 원칙).

## 1. 컨텍스트
- 심사 대상: {{산출물 파일 경로 — 원문만 읽는다. 제작 배경 설명 금지}}
- 평가자: {{누구인가 — 역할·바쁨 정도·전문성 수준·무엇에 거부감(예: 과장·전문용어·긴 문서)}}
- 평가자가 이미 공개한 신호: {{그 사람의 발언·기준·취향을 담은 1차 자료 요지 — 회의록 발언, 공개 기준, 과거 피드백. 없으면 "없음 — 역할 통념으로 역설계" 명시}}

## 2. 지침
- **행동 모델 먼저**: 채점 전에 이 평가자가 산출물을 어떻게 소비하는지 모델을 세운다 — 얼마나 시간을 쓰는가, 어디부터 읽는가, 어디서 읽기를 멈추는가, 무엇이 거슬리는가.
- **루브릭 역설계**: 평가자 신호(위 1차 자료)에서 채점 기준을 도출한다. 신호가 없으면 역할 통념으로 만들고 각 항목에 `[추정]` 표시.
- **기준선은 실제 평가자보다 높게** — 높은 기준에서 통과한 산출물이 낮은 기준의 고득점보다 낫다.
- **블라인드 유지**: 산출물 원문만 근거로 삼는다. 제작 의도를 상상해서 점수를 보정하지 않는다.
- 후하게 채점 금지 — 의심스러우면 감점. 칭찬 나열은 채점이 아니다.

## 3. 산출물
`{{outputs/<레인>.md 절대경로}}` 에 Write:
1. 평가자 행동 모델 (3~5줄)
2. 루브릭 표 — 항목 | 가중치 | 근거(평가자 신호 또는 [추정])
3. 첫 30초 시뮬레이션 — 어디서 멈췄고 그 순간 무슨 인상이었나
4. 항목별 채점 + 근거 (산출물 원문 인용)
5. 거절 시나리오 — 이 평가자가 거절한다면 정확히 어디서, 왜
6. 판정: 통과/조건부/거절 + **고치면 효과 큰 순 개선 2~3개** (실행 가능한 문장으로)
다른 파일은 만들지도 수정하지도 않는다.

- 평가자 신호와 [추정]을 섞지 말고 구분 유지
