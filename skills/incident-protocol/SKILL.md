# incident-protocol — 사고 → 시스템 반영 (메타루프)

사고 1건 = 룰 후보 1건. 사과·요약으로 끝내지 않고 **그 턴에 시스템을 수정**한다. 루프 시스템(스킬·에이전트·워크플로우)이 자기 실패를 먹고 갱신되는 메타루프의 이벤트-구동 절차.

## 절차

1. **원인을 증거로 확정** — 추측 픽스 금지. 재현 명령·로그·git 상태 등 결정적 확인이 먼저다.
2. **방지책을 "그 행동을 만든" 자산에 직접 반영** — 반영처 우선순위:

| 잘못된 행동의 출처 | 반영처 |
|---|---|
| plugify 스킬/에이전트/워크플로우 | 해당 `SKILL.md`·`agents/*.md`·`workflow.mjs` 수정 + **git 커밋** + 에이전트 변경 시 `install.sh` 재실행 |
| 프로젝트 고유 프로세스 | 그 레포 `AGENTS.md` / `.planning/STATE` 프로세스 노트 |
| 하니스 동작(훅·권한·자동화) | `settings.json` (update-config 스킬) |
| 기기 로컬 `~/.claude/CLAUDE.md` | **최후 수단** — 버전관리 밖·이식 불가·타 도구 비가시. 정본은 항상 위 셋 중 하나 |

3. **메모리는 사례 기록만** — "왜 생겼나" + 반영처 포인터를 남긴다. 행동 규칙을 메모리에*만* 두지 말 것 — recall 이 확률적이라 룰 저장소로 부적합.
4. **회귀 케이스 추가** — 사고를 재현하는 eval 케이스(또는 기존 케이스의 채점 항목)를 plugify `evals/<스킬>/` 문제집에 추가한다(규약 = `evals/README.md`). 문제집이 두꺼워지는 것이 메타루프의 연료 — 같은 사고는 다음부터 사람이 아니라 시험이 잡는다.
5. **가지치기 동반** — 기존 룰과 겹치면 추가하지 말고 통합한다. 사고마다 룰을 쌓기만 하면 SKILL 비대화 = 컨텍스트 오염으로 역효과.
6. **첫 실전 관찰 명시** — 룰·스크립트 변경 후 **첫 실행 1회를 관찰 대상으로 선언**하고, 그 실행이 변경을 실증해야 사고가 닫힌다(루프를 고치는 변경도 검증 대상이다).

## 금지
- 사과·요약으로 종결 (자산 수정 없이 턴 종료)
- 메모리에만 기록하고 시스템 반영 생략
- 사람 승인 없이 판정 기준을 완화하는 방향의 "개선" (굿하트 게이밍)
- 검증 없는 워크플로우 스크립트 수정 출하 (최소 구문검증 + 첫 실전 관찰)
