# 실제 낭독 편집과 후속편 한 쌍 라우팅

## 정본과 적용 범위

`godowon-office`는 유효한 `GODOWON_OFFICE_HOME` override 또는 실제 Plugify
Git checkout의 workspace-parent 아래 같은 이름의 sibling에서 찾는다.
없으면 다른 기기 경로를 추측하지 않는다. 해당 레포 AGENTS.md/POLICY.md를
읽고 다음 문서를 읽는다.

- `godo-hymns/찬송편지-후속편-제작-플로우.md`
- `godo-hymns/production-rules/recorded-narration-edit.md`
- 요청이 07·08편이면 `godo-hymns/production-rules/07-08-production-brief-2026-08-28.md`
- 시각 자산 작업이면 `godo-hymns/찬송편지-시각자산-결정규칙-v1-2026-08-28.md`와
  `godo-hymns/찬송듣기-썸네일-결정규칙-v2.1-2026-08-28.md`

이 경로가 없는 오래된 checkout이면 최신 원격 문서를 읽기 전용으로 확인하거나
별도 worktree에서 준비한다. 사용자 변경을 덮어쓰거나 legacy inventory를
바꿔 07·08을 억지로 통과시키지 않는다. 프로젝트의 source·release·runtime
검증이 통과하기 전까지 이 문서만으로 렌더 가능/승인이라고 보고하지 않는다.

## 작업이 빠져나가면 안 되는 경계

- 원본 낭독 + 대본 → 이전 491·370 EDL/실제 편집기/공통 master 근거 확인 →
  대본·실제 발화 대조 → **이번 녹음의 새 EDL** → 정상 테이크 trim/concat →
  편집 WAV → 공통 speech master → 편집 후 시간축 SRT → 청취·QC → 편별 영상.
- 이전 편은 방법·호흡·음량의 근거다. 다른 곡의 컷 시각·대본·자막을 복사하거나
  1–6편의 이미 승인된 결과를 다시 가공하지 않는다.
- 전사는 위치 찾기 보조다. 필요하면 실제 도구를 짧은 구간으로 먼저 검증하고
  완료 구간·타임스탬프를 즉시 저장한다. CPU/프로세스/대기 시간은 진행률이나
  완성 음원 증거가 아니다. 실패 후 전체 녹음을 무작정 처음부터 재처리하지 않는다.
- 실패 테이크와 재시작만 근거 있게 제거하고 정상 호흡·말끝을 보존한다.
  불확실한 컷과 대본/정상 발화 차이는 표시·보고하며 몰래 합성/교정하지 않는다.
- TTS 거부와 썸네일 제작 보류 같은 사용자의 결정은 새 작업에서도 유지한다.
  룸톤 접합과 말소리 mastering을 노래용 음색변환·전체 배속으로 대체하지 않는다.

## 한 쌍 완료와 전달

현재 07은 실제 낭독 간증, 08은 기존 승인 387장 노래 카탈로그를 쓰는
찬송 듣기다. 08의 natural-Amen 검사·전곡 승인·가사 타이밍은 별도이며,
07 낭독이나 미승인 새 노래로 채우지 않는다.

모든 찬송듣기 편은 추가 앞 무음과 원음 자체의 선행 무음에는 자막을 표시하지
않는다. 실제 반주가 시작되는 시점부터 첫 가사 onset 직전까지 장 번호 없는
곡명을 표시하고, 첫 가사 시작점에서 가사 cue로 gap·overlap 없이 전환한다.
반주 onset·곡명 cue 구간·첫 가사 handoff를 렌더 영수증으로 검증하며, 이 곡명
cue는 승인 가사 원문 보존 검사와 분리한다.

요청된 두 편 각각 MP4·독립 청취용 음원·같은 stem의 한국어 SRT·썸네일·
영상 배경·QC·업로드 문안, 간증의 EDL/편집기록까지 납품 목록으로 확인한다.
썸네일/배경은 별도 자산이며 08의 PSD 규칙을 07에 자동 적용하지 않는다.
프로젝트의 최신 시각 규칙·음원 규격을 이 문서에 복제하지 않는다.

01–06 최종 결과물처럼 게시 문안을 함께 전달할 때는 간증·찬송듣기 제목을
각각 만들고, 승인 간증 대본에 근거한 본문은 한 쌍이 공유한다. 찬송듣기 편에만
정본 제작·문의 안내를 본문 맨 아래 붙인다. 두 제목·공용 본문·짝수편 전용
안내를 한 쌍 UTF-8 TXT로 묶어 해당 결과 폴더의 필수 역할로 검증한다. RTF는
만들거나 전달하지 않는다.

썸네일에서 사용자가 선택한 공용 감성문구는 홀수 간증편 게시 제목의 핵심
문구이기도 하다. 잠긴 1행·2행을 공백 하나로 이어 시리즈명 바로 뒤에 그대로
넣고, 별도의 유사 문구나 요약 제목을 만들지 않는다. 짝수 찬송듣기편 제목은
곡명 중심의 기존 형식을 유지한다. 게시 문안 생성기는 이 관계가 다르면 실패해야
한다.

공용 본문은 01–06 최종 문안처럼 실제 내용 전환마다 `[부제목]` 형식의 구간
제목을 둔다. 공통 도입 뒤에 승인 대본을 부제목 없이 통째로 붙인 문안은
미완료다. 최소 네 개 이상의 부제목을 요구하고, 부제목을 제거하면 승인 대본의
문구·순서·앞뒤 개행까지 그대로 복원되어야 한다. 한 쌍은 이 부제목까지 정확히
공유하며, 전달 전 TXT를 다시 읽어 부제목 수·순서와 대본 보존을 확인한다.
각 `[부제목]`과 바로 앞 본문 문장 사이에는 빈 줄을 정확히 세 줄
(문자 기준 개행 4개) 두고, 전달 전 TXT에서 이 간격도 검증한다.

누락 자산이나 보류 지시는 항목별로 남기고, 독립적으로 허용된 부분은 진행할
수 있다. 그러나 음원 하나·07 영상만·전사만 있는 상태를 한 쌍 완료로 보고하지
않는다. 후보 생성, 사람 승인, 실제 외부 전달은 각각 다른 상태다. 이 문서는
YouTube·Drive·알림 권한을 추가하지 않는다.
