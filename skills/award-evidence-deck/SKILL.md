# 공적 증빙 PPT 제작

심사자가 짧은 시간 안에 `무엇을 했는지 → 어떤 근거가 있는지 → 규모와 의미가 무엇인지` 판단할 수 있는 사진 중심 PPTX를 만든다. 로컬 PPTX 제작·편집 절차와 산출물 검증은 `Presentations` 스킬을 함께 적용하고, 이 문서는 공적 증빙자료에만 필요한 판단 기준을 추가한다.

## 1. 작업 계약

- 대화, 공적조서, 기존 PPTX와 지정 폴더를 먼저 조사한다. 이미 확인 가능한 사실을 다시 묻지 않는다.
- 공고문·제출 안내가 있으면 내용 설계 전에 슬라이드 수, 파일 크기, 화면비, 필수 항목과 순서, 허용 형식, 지정 파일명을 합격 조건으로 추출한다.
- 공적 내용 한 항목마다 `주장 1개 + 실제 활동사진 + 최소 수치 또는 짧은 설명`을 기본 단위로 삼는다.
- 심사 화면에 제작 과정, 검색 메모, 내부 자산 관리 문구를 노출하지 않는다. `화면 확인`, `자료 찾기`, `재단 보유 사진`, `NAS 사진`, `임시`, `검토 필요` 같은 표현은 슬라이드에서 제거한다.
- 활동 증빙에는 생성 이미지를 쓰지 않는다. 실제 행사·프로그램·서비스 화면만 사용한다.

## 2. 자료 찾기와 출처

1. 사용자가 준 파일과 현재 작업 폴더를 먼저 확인한다.
2. NAS가 범위에 있으면 작업공간의 NAS 색인·문서 지도 계약을 먼저 따르고, 좁혀진 경로만 읽기 전용으로 확인한다.
3. 웹 자료는 공식 홈페이지·공식 채널을 우선하며, 사용자가 지정한 앱이나 브라우저가 있으면 그것을 사용한다.
4. 파일명이나 주변 정황만으로 날짜·장소·행사를 추정하지 않는다. 각 캡션과 수치를 원문·메타데이터·공식 기록에 다시 대조한다.
5. 외부 제출에 사용할 권한과 개인정보를 확인한다. 공식 채널 게시가 곧 재사용 허가는 아니며, 미성년자·명찰·연락처 등 민감정보가 보이면 허용 범위를 확인하거나 안전하게 가린다. 불확실하면 사용자 보유 자료를 우선하거나 사용자에게 승인을 구한다.
6. 공개 웹 출처는 발표자 노트 `[Sources]`에 URL과 확인일을 남긴다. NAS·내부 문서의 정확한 경로와 비공개 식별자는 외부 제출 PPTX에 넣지 말고 로컬 검사 sidecar에 보관한다. 제출본 노트에는 필요한 경우 `기관 내부 기록 · 확인일`처럼 비민감 출처명만 남긴다.
7. 슬라이드의 사진 아래에는 심사에 필요한 짧은 캡션만 둔다. 권장 형식은 `날짜 · 활동/프로그램 · 장소 또는 공식 출처`이며, 내부 저장 위치나 소유 표현은 넣지 않는다. 콜라주는 개별 사진마다 반복하지 않고 사진군과 가까운 공통 캡션을 사용할 수 있다.

캡션에 날짜를 넣었다면 같은 날짜를 본문에 반복하지 않는다. 출처보다 활동 맥락이 중요한 사진은 `청소년 독서 활동 · 프로그램명`처럼 무엇을 증명하는 사진인지 먼저 쓴다.

## 3. 수치 표현

- 숫자는 판단에 필요한 규모만 남기고 단위까지 한 덩어리로 쓴다. 예: `약 400만 명`.
- 화면에서 반올림한 수치를 쓰면 발표자 노트에 확인일, 원수치와 반올림 기준을 남긴다.
- 수치만 나열하지 말고 대상을 바로 붙인다: `약 400만 명 — 이메일·앱·페이스북`.
- 점수·평점 자료가 있을 때 여러 값을 한 문장에 점으로 구분하지 않는다. `4.4 · 4.4 · 4.5`처럼 소수점과 구분점이 섞이는 표현은 피하고, 동일 폭 열에서 `항목명` 위 또는 아래에 `4.4점`을 배치한다.
- 같은 수준의 수치는 글자 크기, 굵기, 색, 기준선과 단위를 통일한다. 한 항목만 줄바꿈되지 않도록 문구나 폭을 조정한다.
- 마지막 요약 슬라이드에 수치가 있으면 숫자를 떠 있는 장식처럼 두지 않는다. `앞선 논리 → 수치 묶음의 의미 → 수치·대상 쌍 → 해석 문장` 순서로 연결한다.

## 4. 사진과 위계

- 서로 동등한 프로그램·사례는 사진 프레임 크기, 캡션 위치, 제목 크기, 설명 위치를 동일하게 맞춘다. 한쪽을 큰 대표 사진, 다른 쪽을 작은 보조 썸네일로 만들지 않는다.
- 사진 아래 정보가 추가되면 사진만 밀어 넣지 말고 `사진 → 캡션 → 제목 → 설명` 전체 세로 스택을 다시 배치한다.
- 사진은 증빙 내용을 알아볼 수 있을 만큼 크게 사용하고, 인물·현수막·활동 장면이 잘리지 않는지 최종 크기로 확인한다.
- 목차·주제 목록의 텍스트는 박스의 기하학적 중앙이 아니라 실제 글자의 시각 중심까지 확인한다. 동일한 항목은 같은 세로 기준선과 들여쓰기를 사용한다.
- 하단 박스나 사진 밴드가 본문을 가리지 않도록 레이어 순서와 여백을 함께 조정한다.

## 5. 문구와 서체

- 심사자에게 필요한 사실과 의미만 남긴다. 제작자가 자료를 어떻게 구했는지 설명하는 문구는 삭제한다.
- 제목은 공적의 의미를, 부제는 활동 방식이나 확장 경로를 말한다. 사진 캡션이 제목을 되풀이하지 않게 한다.
- 기관 지정 서체가 없고 단정한 기업 문서 톤을 원하면 자유 이용이 가능한 한국어 서체를 우선한다. `Wanted Sans` 같은 기업형 서체는 후보일 뿐 모든 덱에 강제하지 않으며, 설치·사용 전 현재 배포 조건과 로컬 설치 여부를 확인한다.
- 최종 PPTX 내부 XML에서 실제 typeface가 의도한 서체인지 확인한다. 화면에서 비슷해 보인다는 이유만으로 통과시키지 않는다.
- 수신자 환경의 글꼴 대체와 줄바꿈 붕괴도 고려한다. 라이선스와 도구가 허용하면 글꼴을 포함하고, 포함할 수 없으면 널리 설치된 대체 서체를 선택하거나 필요한 글꼴과 호환 조건을 사용자에게 알린다.

## 6. 반복 수정과 확정

- 수정본은 기존 확정 전 파일을 덮어쓰지 말고 `-vN.pptx`로 내보낸다.
- 사용자가 특정 버전을 확정하기 전에는 이전 버전과 작업 원본을 유지한다.
- 사용자가 최종 버전을 확정하고 나머지를 지우라고 하면, 확정본과 같은 작업·파일명 stem의 이전 버전 PPTX와 그 검사 sidecar만 후보로 수집한다. 확정본과 무관한 다른 덱은 제외하고, 실제 대상 목록을 확인한 뒤 휴지통으로 옮긴다. PDF·DOCX·사진·빌더·NAS 원본은 별도 지시 없이 삭제하지 않는다.

## 7. 최종 검수

최종본을 내보내기 전에 `references/judge-facing-qa.md`를 읽고 전 슬라이드를 렌더해 한 장씩 실제 크기로 확인한다. 몽타주는 전체 흐름 확인용일 뿐 개별 슬라이드 검수를 대신하지 않는다.

검수 후에는 최소한 다음을 증명한다.

- 캔버스 밖 오버플로와 의도하지 않은 겹침이 없다.
- 캡션 추가로 기존 레이어 간격이 무너지지 않았다.
- 날짜가 본문과 캡션에 중복되지 않았다.
- 동등 사례가 동등한 크기와 정보 위계를 갖는다.
- 점수·평점이 있다면 소수점과 항목 구분이 혼동되지 않는다.
- 마지막 장에 수치가 있다면 위의 논리와 아래의 결론에 연결된다.
- 사용 서체와 최종 파일명이 검증되었다.
- 제출 규격이 주어진 경우 슬라이드 수, 크기, 형식과 파일명이 모두 맞는다.
- 모든 날짜·수치·장소·사진 설명이 실제 출처와 일치하며, 사진 권리와 개인정보 노출 위험을 확인했다.
