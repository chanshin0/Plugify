# 완성 rubric — 9 카테고리 master 체크리스트

> P3(빈칸 발견)의 핵심. 씨앗에 이 9개 카테고리를 돌려 **빠진 것**을 드러낸다.
> **반드시 청중 스코프로 pruning 먼저** (아래 §pruning) — 안 그러면 개인용 도구에 엔터프라이즈 빈칸을 강요해 기획서가 부풀고 오도된다.

각 빈칸은 `{카테고리 · 빠진 것 · 왜 필요 · v1 여부 · 상태(미정/Claude초안/사용자확정)}` 로 등록.

## §pruning — 청중 스코프로 카테고리 잘라내기 (먼저!)

P0에서 분류한 청중 스코프에 따라 카테고리를 켜고/끈다:

| 카테고리 | n=1 개인도구 | 니치 | 넓은 사용자 |
|---|---|---|---|
| 1 여정 단계 | ✅ | ✅ | ✅ |
| 2 역할/페르소나 | ❌ (1인) | ⚠ (소수 협업만) | ✅ |
| 3 주변 화면+entry/exit | ✅ | ✅ | ✅ |
| 4 UI 상태 (Hurff 5) | ✅ | ✅ | ✅ |
| 5 대안/예외 플로우 | ✅ | ✅ | ✅ |
| 6 스캐폴딩 8층 | ⚠ (데이터수명주기·설정만) | ⚠ (auth·온보딩 경량) | ✅ (전부) |
| 7 엣지 케이스 | ✅ | ✅ | ✅ |
| 8 비기능/교차 (NFR) | ⚠ (프라이버시·성능만) | ✅ | ✅ |
| 9 미결정 질문 | ✅ | ✅ | ✅ |

**규칙**: `❌`는 빈칸으로 올리지 않는다. `⚠`는 해당 하위항목만. 끈 카테고리는 기획서에 "(스코프상 제외)"로 1줄 명시 — 빠뜨린 게 아니라 *의도적 제외*임을 보이게.

## 9 카테고리

### 1. 여정 단계 (Universal Job Map 8)
`references/job-map.md`의 8단계 — 빈 단계 = 빠진 것. Define/Locate/Prepare/Confirm/Execute/Monitor/Modify/Conclude.

### 2. 역할 / 페르소나
- 누가 이걸 하나? 1인 / 팀 / 계층(admin·리뷰어·게스트·통합봇)?
- 역할별로 진입점·권한·성공기준·에러처리가 다른가?
- *n=1이면 대개 스킵.*

### 3. 주변 화면 + entry/exit
- **진입점**: 어떻게 도달? (홈·네비·링크·알림·검색)
- **다음 화면**: 성공 후 어디로? 상세뷰? 다음 작업?
- **이탈점**: 나가는 길 (뒤로·취소·로그아웃·도움말)
- **대안 진입**: 검색·필터·정렬·빈 데이터 상태에서의 시작

### 4. UI 상태 (Scott Hurff "UI Stack" 5상태)
**모든 화면**이 이 5개를 가져야 함. 씨앗은 보통 ideal만 담음:
1. **Ideal** — 데이터 충분, happy path (씨앗)
2. **Empty** — 데이터 없음 (첫 사용·결과없음·삭제후) → 온보딩 CTA
3. **Loading** — 가져오는 중 → skeleton/spinner/진행률
4. **Partial** — 일부만 로드 → 부분 상호작용 가능?
5. **Error** — 잘못됨 (입력오류·서버·권한·타임아웃) → 메시지 + 재시도/수정/지원

### 5. 대안 / 예외 플로우 (Cockburn use case extensions)
- **Primary**: happy path (씨앗)
- **Alternate**: 유효한 분기 (예: 1명에게 vs 그룹에게, 예약발송, 임시저장)
- **Exception**: 시스템이 처리해야 할 에러 (네트워크 실패, 대상없음, 권한거부, 동시편집 충돌)

### 6. 기능→제품 스캐폴딩 8층
*기능 ≠ 제품.* 출시하려면 필요한 층 (스코프로 pruning):
1. **인증/계정** — 가입·로그인·로그아웃·비번재설정·프로필
2. **권한/접근제어** — 누가 뭘 보고/하나? 역할기반? 감사로그?
3. **온보딩/첫실행** — 신규 사용자가 어떻게 발견·학습?
4. **설정/환경** — 기본값·알림·데이터보존·export 포맷
5. **데이터 수명주기** — Create/Read/Update/Delete/Export, 일괄작업
6. **알림/알람** — 언제? in-app/이메일/Slack? opt-in?
7. **도움말/지원** — 인라인 도움·FAQ·문의
8. **오프보딩/데이터처리** — 비활성화·데이터삭제·이탈시 export·보존기간

### 7. 엣지 케이스
빈 리스트 · 최대값(1000개→페이지네이션) · 특수문자/이모지/RTL/긴 이름 · 느린 네트워크 · 동시편집/충돌 · 만료된 토큰 · 오프라인 · 타임존 모호성 · 브라우저 중도 종료(상태복구).

### 8. 비기능 / 교차 관심사 (ISO 25010)
성능(응답<Xms) · 신뢰성(재시도·복구) · 사용성/접근성(WCAG·키보드·스크린리더) · 보안(인증·암호화·injection) · **프라이버시**(동의·보존·삭제·GDPR) · 호환성(브라우저·기기) · 이식성(export·API).
- *n=1이라도 프라이버시·성능은 본다 (녹음·개인데이터 다루면 특히).*

### 9. 미결정 질문 (Example Mapping red cards)
씨앗을 채우다 나온 *결정 안 된* 것: 비즈니스 룰 모호 / 규제·컴플라이언스 / 기술 제약 미탐색 / "이건 v1? v2?". 채우지 말고 Open questions로 올린다.

## 출력 형식 (P3 빈칸 맵)

```
## 빈칸 맵 (스코프: <n=1/니치/넓음>, 제외 카테고리: <…>)

### [카테고리 N: 이름]
- ⬜ <빠진 것> — 왜 필요: <…> — v1? <Y/N/?> — 상태: 미정
- ⬜ ...
```

빈칸은 **happy path가 가정하는 것을 역산**해서 찾는다. "이 화면이 보이려면 데이터가 있어야 → 없을 땐?(empty) 가져오는 중엔?(loading) 실패하면?(error)" 식으로.
