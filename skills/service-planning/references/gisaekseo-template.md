# 기획서 템플릿 — 고정 10섹션

> P5에서 이 구조로 `기획서.md`를 합성. 결정성: 항상 같은 10섹션 (해당없는 섹션은 "(스코프상 제외: 이유)"로 남긴다 — 삭제하지 않음, 빠뜨린 게 아니라 의도적 제외임을 보이게).

```markdown
# 기획서 — <서비스/씨앗 이름>
> 생성: <YYYY-MM-DD> · 스코프: <n=1/니치/넓음> · 티어: <napkin/standard/deep>

## 1. 씨앗
- **원본**: <사용자가 던진 자유 텍스트 그대로>
- **타입**: 기능 / 시나리오 / 화면
- **청중 스코프**: n=1 개인도구 / 니치 / 넓은 사용자

## 2. 정착된 Job
- **Job Story**: When <상황>, I want to <동기>, so I can <결과>.
- **trigger**: <무엇이 이걸 촉발>
- **outcome**: <진짜 얻으려는 것>

## 3. 백본 / 여정 맵

- **<빈칸>** → 결정: <…>  [추정: <뒤집힐 수 있는 가정>] (있으면) 근거: <패턴/출처>

주요 화면별:

## 7. v1 스코프 (appetite: <시간예산>)

- critic 결과 (또는 self-check): 남은 누락 <N개> — <목록>
```

## 작성 규칙
- §4(빈칸 맵)가 이 문서의 심장 — 가장 공들여서.
- §5에서 흔한 엣지(에러=토스트, 빈상태=placeholder+CTA, 로딩=skeleton)는 Claude가 바로 정하고 짧게 명시. 결과 바뀌는 것만 `[추정]`.
- §7: 완성 = 전부 아님. walking skeleton부터.
- 모든 사실 주장은 근거 or `[추정]`. 사용자 없는데 "검증됨" 금지.
