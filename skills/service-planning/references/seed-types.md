# 씨앗 타입별 확장법 + 워크드 예시

> 씨앗은 보통 **기능 / 시나리오 / 화면** 중 하나로 온다. 타입마다 백본 매핑·빈칸 발견의 진입각이 다르다. P0에서 분류, P1~P3에서 타입에 맞게 확장.

---

## A. 기능 (FEATURE) 씨앗
예: "사용자가 데이터를 export 할 수 있다", "회의 녹음에서 할 일 추출"

**진입각**: 하나의 *능력(capability)*. → **Job으로 전환**부터. "왜 이걸 하지?"를 물어 진짜 맥락을 드러냄.

확장 순서:
1. **Job 전환**: 능력 → "When <상황>, 사용자는 <이 능력>으로 <결과>를 원함"
2. **Job Map 8단계**로 그 능력 주변 채우기 (Prepare: 무슨 데이터? Confirm: 미리보기? Conclude: 어디로 내보내나?)
3. **변형**: 포맷·옵션·역할별 차이 (analyst는 raw CSV, exec는 차트)
4. **UI 상태** 5개 + **스캐폴딩**(권한·설정·알림·데이터수명주기)

빈칸 특징: 기능 씨앗은 *주변 lifecycle·역할·통합*이 가장 많이 빠져 있다.

---

## B. 시나리오 (SCENARIO) 씨앗
예: "사용자가 3개월 전 대화를 찾고 싶다"

**진입각**: 하나의 *사용자 목표/여정*. → **Job Story로 정착**부터 (When/want/so-that + trigger).

확장 순서:
1. **trigger·outcome 명시**: 뭐가 이걸 촉발? (회고 중 "왜 X로 정했지?") 진짜 결과는? (의사결정 근거 문서화)
2. **before/during/after 여정**: 이르게 된 계기 → 검색/스크롤/필터 → 찾은 뒤 인용/export
3. **대안/예외**: 없으면? 삭제됐으면? 언제인지 기억 못하면? 결과 10000개면?
4. **함의된 화면 전부**: 검색입력·필터패널·결과목록·맥락뷰·메시지액션

빈칸 특징: 시나리오 씨앗은 *대안/예외 경로*와 *함의된 화면들*이 가장 많이 빠져 있다.

---

## C. 화면 (SCREEN) 씨앗
예: "내 식물 물주기 대시보드"

**진입각**: 하나의 *UI*. → **entry/exit + 상태**부터.

확장 순서:
1. **진입점**: 어떻게 도달? 이게 진입화면인가 상세뷰인가?
2. **다음 화면**: 각 요소 탭 → 어디로? (식물 탭→상세, 추가 탭→생성플로우, 물주기 탭→확인)
3. **5상태 전부**: ideal/empty(식물 0개)/loading(skeleton)/partial/error
4. **다운스트림 플로우**: 생성플로우·상세뷰·편집을 별도로 그림
5. **데이터 모델·액션**: 각 요소가 가정하는 데이터 + 가능한 액션

빈칸 특징: 화면 씨앗은 *상태(empty/loading/error)*와 *연결된 다음 화면들*이 가장 많이 빠져 있다.

---

## 공통 규칙

- **씨앗은 거의 항상 ideal/happy/Execute만 담는다** — 확장은 "이 happy 상태가 성립하려면 무엇이 전제되나"를 역산하는 것.
- 타입이 애매하면(기능+화면 섞임) 더 *구체적인* 것으로 정착시킨 뒤 나머지를 빈칸으로.
- 청중 스코프(`references/completeness-rubric.md` §pruning)를 항상 먼저 적용.

|---|---|---|---|
| 회의 녹음→할 일 추출 | 기능 | Job Map 8단계 (전사·미리보기·편집·export 암묵) | lifecycle·통합·프라이버시 |
