# voice-note — 음성 → 업무 브레인/세컨 브레인 라우팅

원칙: **기계 단계는 스크립트, 판단 단계는 Claude, 고도원 이사장 수행 업무 녹음(회의·통화·메모·복기 등)은 업무 브레인으로, 비업무 녹음만 세컨 브레인 진입 전 사용자 y/n.**

## 경로 해소 (먼저, fail-closed)
브레인 경로는 기기별 홈 디렉터리를 추측하지 않는다. 각 저장소의 명시적 절대경로 환경 변수(`GODOWON_OFFICE_HOME`·`SECOND_BRAIN_HOME`)가 있으면 먼저 쓰고, 없으면 이 스킬을 소유한 활성 Plugify 체크아웃의 작업공간 부모 아래 이름이 같은 **형제 저장소** `godowon-office`·`second_brain`을 쓴다. 현재 제품 cwd를 anchor로 쓰지 않는다. 대상이 기대한 Git 저장소가 아니거나 없으면 중단하고 경로를 보고한다. 실제 해소는 그 Plugify 체크아웃의 `scripts/workspace-migrate.py --resolve <repo>`를 호출하고, 정본 계약은 `docs/WORKSPACE_MIGRATION.md`를 따른다.

## 0. 자동 수신
launchd 에이전트 `com.chanshin.voice-watch`(정본: 이 폴더 `bin/voice-watch`)가 맥 음성메모 폴더와 `~/Inbox-음성`(갤럭시 Syncthing 수신)을 감시한다:
- 새 *.m4a → 안정화 확인 → 원장(`~/.local/state/voice-note/ledger.jsonl`, 멱등) → 시각·길이 겹침 짝짓기(이중 녹음의 늦게 온 쪽은 백업 보관만) → `~/Documents/옹달샘-대화/{날짜}/`로 아카이브 + voice2text 본전사 → macOS 알림
- 처리 대기 표시는 날짜 폴더의 `.pending-review` — Claude 세션은 이 마커를 보면 §3 정리본부터 이어가면 된다 (전사는 이미 되어 있음)
- **프라이버시 규칙**: 알림·텔레그램 등 외부 채널에는 메타데이터(파일명·길이·상태)만. 회의 내용·요지는 싣지 않는다 — 봇 채널은 종단간 암호화가 아니다
- 로그·권한 문제는 `~/.local/state/voice-note/watch.log` 확인

## 1. 전사 + 품질검증
```
voice2text <음성파일> [출력폴더]     # ~/.local/bin — 처방(-mc 0) 내장
```
- 스크립트 정본은 이 스킬 폴더의 `bin/voice2text` — 수정 시 `~/.local/bin/voice2text`에 재복사(설치본과 드리프트 주의).
- 상태 `SUSPECT`면 스크립트가 알려주는 3지점 샘플 전사로 원인 확인:
  말소리가 있는데 전사가 죽었으면 → 재전사(이미 -mc 0이므로 -et 조정 또는 구간 분할),
  원래 무음·음악·배경영상이면 → 그대로 진행하고 정리본에 표기.
- 30분 넘는 파일 여러 개면 병렬 실행 가능(GPU 공유라 배속은 아님을 사용자에게 고지).

## 2. 보관 (3층 구조의 원본층)
- 기존 주제 폴더가 있으면 거기로: 예) `~/Documents/옹달샘-대화/{YYYY-MM-DD}/`
- 없으면: `~/Documents/음성노트/{YYYY-MM-DD}-{slug}/`
- 원본 음성 + transcript-*.txt/srt 를 함께 둔다. 원본은 절대 삭제하지 않는다(오전사 복구의 유일한 수단).

## 3. 정리본 (판단 단계)
전사가 길면(대략 20분↑) 격리 서브에이전트에 위임(**model 명시: sonnet** — 통상 추출 작업), 짧으면 직접.
정리본 산출물은 녹음 유형에 맞는 정본에 `노트-<이름>.md`로 생성한다: 비업무는 전사와 같은 폴더, 고도원 이사장 수행 업무 녹음은 §3.1의 업무 브레인 경로.
- 참여자 추정 (호칭·1인칭 서술 등 근거 포함 — 화자 분리가 없으므로 항상 [추정] 표시)
- 주제 타임라인 (srt 타임스탬프 기준)
- 결정된 것 / 제안받은 것 / 숙제 / 다음 일정
- 하이라이트 인용 (원문 그대로, 오인식은 [오타 추정: ~] 병기)
- 전사 품질 메모 (헛말 구간, 판독불가 구간)

규칙: 전사에 없는 내용 발명 금지. 헛말 반복(유튜브 아웃트로류 "다음 영상에서 만나요", "한글자막 제공..." 등)은 대화가 아님 — 필터. 고유명사는 사용자 기억으로 재검증 권장을 명시.

### 3.1 수행비서 모드 (고도원 이사장 수행 업무 녹음)
고도원 이사장 수행 업무 녹음(회의·통화·메모·복기 등)이면 정리본의 최종 산출물은 요약이 아니라 **과제·태스크 도출**이다. 정리본 작성 후:
- **정리본 위치**: 수행비서 모드의 `노트-*.md`·정리 산출물은 전사 폴더가 아니라 **해소된 업무 브레인의 `meetings/{YYYY-MM-DD}/`**에 생성 (원본 음성·전사 경로 링크 필수 — 미디어는 기존 금고 유지). 인물·프로젝트 카드(`people/`·`projects/`) 갱신도 함께. 정본 규칙은 그 레포 `POLICY.md`
- 숙제·다음 일정·핵심 요청을 실행 가능한 과제로 변환: 과제 한 줄 / 담당 / 근거(노트 타임스탬프) / 다음 액션 1개
- 해소된 업무 브레인의 `TASKS.md`(수행 과제 보드)에 append — 열린 과제·다가오는 일정·완료 3구획, 원본 노트 링크 필수
- 화자 분리가 없으므로 참여자·담당·고유명사는 **사용자 교정을 받은 뒤** 확정 기입 (교정 전엔 [추정] 표시)
- **세컨 브레인 캡처 금지**: 수행 업무 요지는 `second_brain`에 캡처하지 않는다. 해소된 업무 브레인의 노트·`people/`·`projects/` 카드가 정본이다. §4의 y/n 게이트는 수행 업무 외 녹음에만 적용.

## 4. 세컨 브레인 게이트 (비업무 녹음만, 사용자 confirm)
비업무/개인 녹음의 정리본에서 리트머스(second_brain **POLICY.md** §2.1: 휘발성 필수 + 사거리·갱신 중 1개) 통과 후보를 2~5개 뽑아 한 줄씩 y/n 제안. 승인된 것만:
```
second_brain_home="<위 경로 계약으로 해소한 절대경로>"
cd "$second_brain_home" && bin/idea quick "<제목>

<요지 — 자기 언어 요약, 핵심 인용 포함 가능>

(원본: <보관 폴더 경로>)" -t <본문 명시 키워드만>
```
캡처 후 `bin/idea ingest <id>` — wiki 후보 점수≥2면 합치기 제안(레포 룰 §11).

**금지**: 전사 전문 통째 캡처 · 확인 없는 자동 캡처 · 본문에 없는 추측 태그 · `sources/` 직접 생성 · **기존 source 본문 수정**(정정도 새 source로 — POLICY §3 출처 불변).
