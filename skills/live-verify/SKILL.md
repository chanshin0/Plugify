# live-verify — 루프 종결 신호를 "게이트 통과"에서 "라이브 동작"으로

게이트 전부 초록 ≠ 실제 동작 (직렬 마스킹·환경 차이·배포 누락 — niche-market Bug-9→10 실사고). 이 스킬은 픽스/기능 보고의 종착점을 **"배포된 환경에서 그 경로가 실제로 됨(증거 포함)"** 으로 옮긴다. 메인이 직접 수행한다(판정·보고는 메인 책임, 서브에이전트 불필요) — 폴링 잡음만 background Bash 에 격리.

> **역할 재배치(★1 Phase C, 2026-07-03)**: task 의 프리뷰-판정 가능한 라이브 확인은 spec-building **라이브 게이트**(`{PREVIEW_URL}` 항목)가 merge 전에 자율로 닫는다. 이 스킬의 담당 = **prod 최종 확인**(사람이 main merge/push 한 뒤 — 프리뷰에서 닫힌 항목은 스팟체크, 프리뷰로 판정 불가한 경로는 전체) + 라이브 게이트 없는 변경의 기존 전 절차. P3 실패 시 버그 블록의 수용 기준에는 가능하면 `{PREVIEW_URL}` 라이브 게이트를 포함시켜 다음 바퀴가 프리뷰에서 닫히게 한다.

## 입력 (메인이 STATE·레포에서 준비)
- **검증 시나리오 1개**: "어디서 무엇을 하면 무엇이 보여야 한다" — 직전 task 의 증상/수용 기준에서 도출
- **배포 방식·URL**: push=자동배포 여부, 배포 도메인 (STATE/README/플랫폼 설정에서)
- **배포 마커**: 새 배포 반영을 확인할 결정적 신호 (P1 전략)

## P0 — push 실재 확인
`git log origin/<branch> -1`·`git status --short` 로 검증 대상 커밋이 원격에 있는지 확인. **워크플로우/에이전트의 committed·pushed 보고를 믿지 않는다 — git 상태가 SSOT** (2026-06-11 committed 오보고 사고).
- **push 미실재면 여기서 정지.** 행동 = **"push/배포 먼저"** (push 는 비가역 경계 = 사람 몫 — executor 가 대신 `git push` 하지 않는다). push≠자동배포면 배포 트리거 누락도 동일 처리.
- 이건 **코드 버그가 아니라 미완료 액션**이다 → **표준 버그 블록·spec-building 대상 아님**. STATE 에 버그 블록을 적지 마라 — 버그 블록은 *코드 실패*를 구현으로 되돌리는 인터페이스라, push 누락에 쓰면 spec-building 으로 오라우팅된다(고칠 코드가 없는데 재구현). "push 하면 닫힘"으로 끝맺는다(git 상태가 이미 SSOT).

## P1 — 배포 반영 폴링 (background Bash)
마커 전략, 위에서 아래로:
1. **클라이언트 가시 변경**: 그 변경이 만든 정적 에셋 차이를 grep (예: 페이지에서 CSS URL 추출 → 새 속성값 `blur(40px)` 확인)
2. **빌드 ID 변화**: 서버 전용 변경 대비 — **push 전에** 현재 정적 에셋 해시를 캡처해두고 변화를 대기
3. **마커 없음**: 직전 배포 소요시간 ×2 대기 후 P2 진행, 판정 실패 시 1회만 재대기
폴링은 `run_in_background` Bash 루프(sleep 20×N, 상한 ~5분). dev 서버 기동 금지.

## P2 — 증상/수용 경로 재실행
- **프로브로 충분하면 프로브**: 비로그인 GET 경로는 curl (상태코드·본문 마커) — 브라우저보다 싸고 결정적
- **사용자 플로우면 브라우저**(Claude in Chrome): `tabs_context` → **새 탭** 생성 → 경로 재현. 실전 함정 2개(2026-06-11 실측):
  - React controlled input 은 `form_input` 이 상태에 안 잡힐 수 있다 → **필드 클릭 후 `computer type` 실제 타이핑**
  - 페이지 로드 직후 좌표 클릭은 하이드레이션 전에 유실될 수 있다 → 로드 대기 후 클릭, 무반응이면 ref 클릭/재시도
- **금지**: 최종 submit·게시·결제·삭제 등 비가역/외부가시 액션은 클릭하지 않는다 — 직전 단계까지로 판정하거나 사용자에게 넘김. 시크릿·자격증명 입력 금지. 로그인 세션이 필요한데 없으면 로그인만 사용자에게 요청.

## P3 — 판정·행동
- **평가 불능 = 실패**: 검증 항목은 assertion 자체가 성공을 보고해야 통과다. 프로브가 assert 전에 죽음·응답 파싱 불가·마커 매치 0건·브라우저 단계 미실행이면 실패지 통과가 아니다. 부수효과(로그에 요청 찍힘·에러 안 보임·파일 생김)로 pass 추론 금지 — 평가 불능이면 체크(또는 코드)를 고쳐 재실행한다.
- **성공**: 증거(스크린샷·응답 마커) + "라이브 검증 ✅" 로 보고, STATE 해당 task 에 한 줄 기록. 테스트 잔여물(드래프트 등) 만들었으면 명시.
- **실패**: 아래 **표준 버그 블록**을 STATE `## 다음 task` 최상단에 append → spec-building 재투입 제안(진행은 메인 게이트). 원인 미상 실패면 블록 작성 전에 **debugger 로 원인 확정**부터 — 원인 없는 픽스 task 금지. (단 **P0 에서 막힌 push/배포 미실재는 코드 실패가 아니므로 버그 블록 대상 아님** — P0 의 "push 먼저"로 끝낸다.)

### 표준 버그 블록 (진단→구현 공용 인터페이스 — debugger·perf-review 산출도 이 양식으로 수렴시킨다)
```
**Bug-N: <한 줄 증상>** (<날짜> <발견 경로: live-verify/debugger/사용자>)
- 증상: <어디서 무엇을 하면 무엇이 됨/안 됨 + 에러문구 원문>
- 원인(확정/미상): <확정이면 file:line + 메커니즘 + 재현 출력. 미상이면 "debugger 진단 필요">
- 재현: <결정적 재현 명령/경로 — 실코드 경로 경유>
- 수용 기준: <항목별> + 4게이트 + **live-verify 재통과** (실경로 실증 — 최소 재현 복사 금지)
```

### 지점 노트 (`.planning/notes.md` — append-only, 규약 정본)
사이클 종결 시(P3 판정 후, 또는 spec-building 커밋/라이브 게이트 통과 후) 이번 사이클에서 배운 **"코드가 말해주지 않는 것"** 이 있으면 메인이 1~3줄 append 한다. 없으면 안 쓴다(소음 금지).
- 형식: `- <YYYY-MM-DD> <증상/함정/결정> → <원인/메커니즘/이유> → <대응/규칙>`
- 기록 기준(전부 충족): ① 코드만 읽어서는 알 수 없다 ② 다음 에이전트의 작업이 달라진다 ③ 없으면 뭔가 깨진다
- 금지: 코드가 이미 보여주는 것 · 일반론 · 이번 대화에만 유효한 것 · 문서 자신에 대한 서술
- **양방향**: 이번 변경이 기존 노트 줄을 낡게 만들었으면 그 줄을 정정한다(삭제 대신 정정 표기)
- 반복 함정·검증 절차가 3회+ 쌓이면 지점 AGENTS.md 로 승격 검토(사람 게이트)

## 루프 상한 (폭주 방지)
- 검증→픽스→재검증 **최대 3바퀴**, 미해결이면 멈추고 사용자 에스컬레이션.
- 같은 증상이 2바퀴 연속 동일하면 픽스 재시도 금지 — debugger 재진단부터 (같은 에러에 같은 시도 반복은 학습이 아니라 spinning).

## 금지
- 게이트 통과만으로 "해결" 보고 (이 스킬의 존재 이유)
- 비가역 액션 클릭 · 시크릿 입력 · prod 데이터 불필요 오염
- 마커/대기 전략 없이 "아마 배포됐을 것" 추정 진행(P1) — 판정 불가 시 실패 처리는 P3 참조
